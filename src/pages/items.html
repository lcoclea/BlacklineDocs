Every item in Blackline is one data asset, an Item Definition. You create it in the Content Browser, fill its fields in the Details panel, and the stash, the traders, the loot screens and the inspect window all read it. No code is needed.

Make your first item

  1. Create the asset In the Content Browser, right-click and choose Miscellaneous > Data Asset. Pick Item Definition as the class. Give it a name that is unique in your project, such as PDA_AR4. The name becomes the item's id.
  2. Fill the basics Set Display Name, Description, Footprint (cells wide by cells high), Value and Weight in kilograms.
  3. Tag it Add a gameplay tag to Tags that says what it is, such as Item.Weapon.Rifle. You make these tags yourself in Project Settings > Gameplay Tags. Categories, container rules and menu rows all read them.
  4. Pick a type Open the Type dropdown and choose one, such as Weapon. That type's own fields appear underneath.
  5. Give it a look Under Look, set Static Mesh to the item's mesh. The tile and the inspect window render it. Or set Icon to a texture if you already have a picture.
  6. Save The item now exists for every screen. You do not register it anywhere.

The asset is found for you

The plugin registers the Item Definition type with the Asset Manager when it starts. It scans every content root in the project, including game feature plugins, and marks the assets to always be cooked, because nothing references an item directly. You do not edit DefaultGame.ini.

Everything else refers to an item by its primary asset id, which is the type NVSViewItem and the asset name, such as NVSViewItem:PDA_AR4. Fields that take an item, such as a starting item or a trader's stock, show a picker that lists only items. Nothing loads until a tile shows it.

Run Asset Actions > Validate Assets on your items. The definition reports mistakes such as a missing type, a weapon with no equip slot, an attachment with no kind or a trait listed twice.

The fields every item has

Display Name, Description
The name on the tile and the paragraph in the inspect window.
Footprint
Cells it covers, width by height, before rotation. A 4 by 1 rifle lies flat.
Value
The price in whole currency units. The inspect window shows it as VALUE, and traders and the market use it.
Weight
Kilograms. Tiles show it times the stack count, and it counts toward carried weight while the item is worn or carried.
Tags
What the item is. Category tabs, container accept rules and menu rows match against these.
Rarity
A gameplay tag stored on the item for your game to read. The shipped screens do not use it yet.
Type
The kind of item. One per item. See below.
Traits
Extra behaviour any type can carry, such as stacking. See below.
Icon
A texture used instead of a rendered picture. Leave it empty to render one from the look.
Look
How the item is drawn on tiles, in the inspect window and on the body: a Static Mesh, a Skeletal Mesh (used when Static Mesh is empty, such as for trousers that follow the body) or a Pickup Actor (such as a fully built rifle Blueprint), plus an optional Framing override. See Character looks.

Item types

Each type adds its own fields under Type, and picking a type shows only that type's fields. The wearable types, Weapon, Armour, Container and Gear, also have Worn On and Worn Offset, which place the item on the character while it is worn. See Equipment. The type also gives the item its word on the tile when no category names it, such as WEAPON.

Weapon
Equip Slot (such as NVS.View.Slot.Primary or NVS.View.Slot.Sidearm), Worn On, Worn Offset, Fire Modes and Attachment Slots. Each attachment slot has a Slot tag, a Label, an Accepts list of kinds, and a Socket and Offset for where a fitted part sits. The raid HUD reads the first fire mode of the worn primary. Calibre is stored for your game. See Weapons.
Attachment
Kind, such as Attachment.Optic. A weapon slot whose Accepts holds that kind takes it.
Ammo
Kind is the weapon slot a magazine loads into, such as Attachment.Magazine.AR4. Capacity is the rounds it holds, which the raid HUD shows while it is fitted. Leave both empty for loose rounds. Calibre is stored for your game.
Armour
Equip Slot, such as NVS.View.Slot.Armour or NVS.View.Slot.Head, Worn On and Worn Offset. Armour Class and Protected Zones are stored for your game.
Consumable
Heals is the hit points it gives back to a body zone on the health screen. Food and Water are added when the player uses it from a grid. Uses, Use Seconds and Effect are stored for your game. Consumables are the items that get a Use row.
Container
Grids (a label and a size each, so a rig can have several pouches), Equip Slot (such as NVS.View.Slot.Pack, empty for a crate), Worn On, Worn Offset, Accepts (a tag query, empty takes anything), Refusal Text and Place. See Containers.
Gear
Equip Slot, Worn On and Worn Offset for worn gear such as a headset, gloves or trousers. Leave Equip Slot empty for loose gear such as salvage or grenades.
Key
Opens and Uses, stored for your game.
Quest Item
Task, the task definition that wants it, stored for your game.
The fields marked as stored for your game are kept on the asset and readable in Blueprint, but no shipped screen acts on them yet. Read them from the definition when your game needs them.

Traits

Traits are added from the Traits list with the plus button. An item carries each trait at most once.

Stackable
Max Stack, how many share one cell. Without it an item never stacks. Adding items tops up partial stacks first, and Shift-click splits a stack in half.
Loot Rule
What happens when someone else loots the inventory this item is in. StaysOnBody means the item cannot be taken off a body, but what is inside it can, like trousers and their pockets. Sealed means nothing about it can be taken or opened, like a secure case. See Containers.
Tradeable
Listable On Market lets the player list it on the market. Sell Ratio is stored for your game.
Quest Locked
Keeps the item off the market. Reason is stored for your game.
Durability
Max Durability, stored for your game.

Categories

An Item Category Definition is one tab on the stash filter and the trade and market rails, such as Weapons or Medical. Create it the same way, as a Data Asset of class Item Category Definition.

Tag
Items whose tags carry this tag, or one below it, belong here. A category for Item.Weapon catches Item.Weapon.Rifle and Item.Weapon.Sidearm. When two categories match, the deeper tag wins.
Display Name
The tab's name.
Icon
The tab's icon by name, such as rifle or med. None shows the name instead.
Sort Order
Lower comes first. Ties sort by asset name.

The category also names the word on the tile. The item's deepest tag under its category is used, so Item.Weapon.Rifle under a Weapons category reads RIFLE. With no category, the tile shows the type's word. The stash rail is built from your categories only when the project has at least one.

Items made at run time

For procedural loot, build an Item Definition object in Blueprint or C++ and call Register Runtime Item on NVS View Definition Library. It is then found by its id like any asset until you call Unregister Runtime Item. Get Item Definition returns the definition for any id, and Get All Item Ids lists every item without loading them.

Result

Add your new item to the player's Starting Items on the Inventory component (see Containers) and press Play. Open the stash. Your item sits in the grid with its name, word and weight, and double-clicking it opens the inspect window with your description, weight and value.
