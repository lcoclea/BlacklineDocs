Every Blackline screen lives on one of five layers, and every screen class names its own layer, so you never pick one when you open it. This page shows how to open and close screens from Blueprint, how to swap a shipped screen for your own, how layers decide input and Escape, and how to build a new screen.

Open a screen from Blueprint

The NVS View Screen Library puts screens on the viewport without any layer code. The first call that needs the layer stack builds it.

  1. Build the layers In your player controller's Begin Play, call Create Layer Stack with Self. With no layout given it uses the one your View Setup Definition names. Calling it again returns the stack already built.
  2. Show the toasts Call Show Screen By Tag with NVS.View.Screen.NotificationStack, so notifications have somewhere to draw.
  3. Open the hub Call Show Screen By Tag with NVS.View.Screen.MainMenu.

The demo's player controller starts the game with exactly these three calls, after looking through its camera. Every screen behind the hub opens from the hub's own buttons.

The screen tags are declared by the plugin, one per shipped screen: MainMenu, InsertionSelect, RaidHUD, SkillsScreen, SkillTree, CharacterScreen, HealthScreen, StashScreen, LoadoutLibrary, RaidInventory, TraderList, TradeScreen, MarketScreen, TaskLog, PartyLobby, SettingsScreen, NotificationStack, RaidSummary, Hideout, BenchScreen and PowerStation, plus the smaller windows such as ItemMenu, InspectWindow and ContainerWindow. Each sits under NVS.View.Screen. See Screens.

Replace a shipped screen

The Screen Registry maps each screen tag to the Widget Blueprint that opens for it. The plugin ships DA_BlacklineScreenRegistry. Every screen that opens another goes through the registry too, so changing one row changes that screen everywhere.

  1. Make your screen Duplicate the shipped Widget Blueprint, such as /NVSBlackline/Screens/W_StashScreen, into your own folder, or make a child of it. Restyle or extend it in the designer.
  2. Make your registry Duplicate DA_BlacklineScreenRegistry into your folder and point the NVS.View.Screen.StashScreen row's Widget at your screen.
  3. Use it In your own View Setup Definition, set Screen Registry to your copy. A game's own setup wins over the one the plugin ships, so nothing else needs to change.

Each registry row has a ScreenTag, a Widget and an optional LayerOverride. Only a screen can stand in for a screen, because the caller pushes it onto the layer that class declares.

The five layers

The layer table is a UNVSViewLayoutAsset. The plugin ships DA_BlacklineLayout, which the View Setup Definition names, with five layers from bottom to top:

TagHolds
NVS.View.Layer.GameThe raid HUD.
NVS.View.Layer.GameMenuScreens over live gameplay: the raid inventory and the task log.
NVS.View.Layer.MenuFull-screen menus, such as the hub and the stash.
NVS.View.Layer.ModalThe match found banner, the drop countdown, the debrief and the desk that container windows open on.
NVS.View.Layer.NotificationThe notification stack and the item menu.

Each row of the layout is an FNVSViewLayerDef:

LayerTag
A tag under NVS.View.Layer. Every push and pop addresses a layer by it.
ZOrder
Higher draws over lower. Declaration order does not matter.
ContainerClass
The CommonUI container. Leave it unset for a stack.
InputConfig
The FUIInputConfig applied when this layer is the highest occupied layer that decides input.
bDecidesInput
When false the layer draws but never takes input, so a toast layer can sit above a dialog without taking its input.
bOwnsBackHandler
Marks the layer meant to own Escape. The current Escape handling does not read it.
TransitionDuration
Zero cuts between screens, which is the default because a crossfade shows the world through both screens.

In the editor, the asset's data validation reports a tag outside NVS.View.Layer or a tag used twice.

Adding a layer

  1. Add a tag In Project Settings > Gameplay Tags, add a child of NVS.View.Layer, such as NVS.View.Layer.Tooltip.
  2. Copy the layout Duplicate DA_BlacklineLayout into your folder and add a row for the new tag with its z-order and input config. Keep the five shipped rows, because the shipped screens declare them.
  3. Use it Set Layout Asset on your View Setup Definition to your copy, or pass it to Create Layer Stack.

Back and Escape

The back keys close the topmost screen. They are Escape for the keyboard and the right face button for a gamepad, and the Engine Settings Setup Definition's Back Keys can name others. The layer subsystem reads them through a Slate input preprocessor, so they work even when no widget has focus.

  1. Layers are walked from the highest z-order down. The first active screen that is visible and does not ignore Back is chosen.
  2. The screen's InterceptBack runs first. The base class clears a selected tile or socket and returns true if it did, so the first press deselects and the second closes. The settings screen reverts a pending display change here.
  3. If nothing intercepted, the screen is removed from its layer and the one below it becomes active.

Four class defaults on a screen change this:

bIgnoresBack
Back passes over this screen to the one below. The raid HUD and the notification stack set it, so Escape closes the menu under the toasts.
CloseKeys
Keys that also close this screen while it is on top. The raid inventory closes on the keys that open it.
BackButtonNames
Buttons in the tree that close the screen, the same way Escape does.
InterceptBack()
Override it in C++ to handle Back some other way, such as closing an inner panel. Return true when you handled it.

While a text field or a key capture needs the back key, call SetEscapeClaimed(true) on the layer subsystem so the key goes to the focused widget, and release it afterwards.

Input

Each time a layer's displayed widget changes, the subsystem picks the highest occupied layer whose bDecidesInput is true, applies that layer's input config through the player's CommonUI action router, and broadcasts the winning tag.

FNVSOnLayerActivationChanged& OnLayerActivationChanged()
Fires on every recompute with the winning layer's tag, or an empty tag when no layer is occupied. Restoring game input when the UI empties is left to your game.
void SetInputConfigOverride(const TOptional<FUIInputConfig>& InOverride)
While set, replaces the winning layer's config. Pass an unset optional to go back to the layers.
bool IsLayerOccupied(const FGameplayTag& LayerTag) const
True while the layer shows a widget. Blueprint pure.

Pushing from C++

UNVSViewLayerSubsystem is a local player subsystem, so split screen gets one stack per player. Pushes are asynchronous because the widget class is a soft reference.

FNVSViewPushHandle PushWidget(const FGameplayTag& LayerTag, TSoftClassPtr<UCommonActivatableWidget> WidgetClass)
Loads the class and adds it to the layer. A null class returns a cancelled handle.
FNVSViewPushHandle RequestPush(const FGameplayTag& LayerTag, TSoftClassPtr<UCommonActivatableWidget> WidgetClass, TFunction<void(UNVSViewLayerSubsystem&)> AfterPush)
The same, then runs AfterPush once the widget is in its container.
FNVSViewPushHandle ReplaceWidget(const FGameplayTag& LayerTag, TSoftClassPtr<UCommonActivatableWidget> WidgetClass, UCommonActivatableWidget& Outgoing)
Replaces Outgoing instead of stacking over it. If an instance already sits below, that one is shown again.
bool PopWidget(UCommonActivatableWidget& Widget)
Removes a widget from whichever layer holds it.
bool PopTopmostWidget()
Removes the topmost screen, as the back keys do. False when nothing is showing.

The handle tracks the load. IsPending, IsCompleted and IsCancelled report its state, and copies share it. Ask a screen class for its layer with UNVSViewScreen::GetLayerTagForClass, so a push site never hard codes one.

From inside a screen

bool PushScreen(TSoftClassPtr<UNVSViewScreen> Destination)
Opens Destination on the layer its class declares, routed through the screen registry. Blueprint callable.
bool ReplaceScreen(TSoftClassPtr<UNVSViewScreen> Destination)
Replaces this screen, as a navigation tab does. C++ only.
bool PopScreen()
Removes this screen, as a back button does. C++ only.

Most screens need no code for this. MenuDestinations maps a button's widget name to the screen it opens, and TabBindings with TabStripWidgetName builds a tab bar whose tabs carry their own destinations.

Writing your own screen

A screen is a UNVSViewScreen subclass with a widget tree. The class says which layer it goes on and what it binds, and the tree holds widgets named so the bindings can find them. This example shows the task tracked into a raid, with its own empty state.

  1. Create the Widget Blueprint Pick NVSViewScreen as the parent class.
  2. Set the layer In Class Defaults, set Layer Tag to NVS.View.Layer.GameMenu.
  3. Add a binding Add an entry to View Model Bindings: Binding Id Task, Domain NVS.View.ViewModel.Record, View Model Class NVSViewRecordViewModel, Source Class NVSViewTrackedTask.
  4. Add readouts Add two entries to Readout Bindings: TaskTitle reading field Headline, and TaskBody reading Body, both from binding Task.
  5. Add the empty state Under Empty State, add Task to Empty When Bindings and fill Empty Title, Empty Body and Empty Setup Hint.
  6. Add the back button Add BackButton to Back Button Names.
// MyBriefingScreen.h
#pragma once

#include "Screens/NVSViewScreen.h"

#include "MyBriefingScreen.generated.h"

UCLASS()
class UMyBriefingScreen : public UNVSViewScreen
{
	GENERATED_BODY()

public:
	UMyBriefingScreen();

	static FName TaskBindingId() { return FName(TEXT("Task")); }
};

// MyBriefingScreen.cpp
#include "MyBriefingScreen.h"

#include "Sources/NVSViewRecordLists.h"
#include "Tags/NVSViewTags.h"
#include "ViewModels/NVSViewRecordViewModel.h"

UMyBriefingScreen::UMyBriefingScreen()
{
	LayerTag = TAG_NVS_View_Layer_GameMenu.GetTag();

	ViewModelBindings =
	{
		MakeBinding(TaskBindingId(), TAG_NVS_View_ViewModel_Record.GetTag(),
			UNVSViewRecordViewModel::StaticClass(), UNVSViewTrackedTask::StaticClass()),
	};
	ReadoutBindings =
	{
		MakeReadoutBinding(TEXT("TaskTitle"), TaskBindingId(), TEXT("Headline")),
		MakeReadoutBinding(TEXT("TaskBody"), TaskBindingId(), TEXT("Body")),
	};
	EmptyWhenBindings = { TaskBindingId() };
	EmptyTitle = INVTEXT("No task tracked");
	EmptyBody = INVTEXT("Track a task in the task log to see it here.");
	EmptySetupHint = INVTEXT("Create Task Definition assets.");
	BackButtonNames = { FName(TEXT("BackButton")) };
}

Parent the Widget Blueprint to UMyBriefingScreen.

In the tree, place two text blocks named TaskTitle and TaskBody, and a W_Button from /NVSBlackline/Widgets/ named BackButton so it carries the theme. Optionally wrap the content in a Scale Box named CompositionScaleBox around a Size Box named CompositionBox. With them the screen lays out at MinimumCompositionSize, 1560 by 900 by default, and scales down below it instead of reflowing.

To open it, add a row for it to your screen registry under a tag of your own and call Show Screen By Tag, or add the button name and the class to another screen's MenuDestinations.

Hooks a C++ subclass can override

OnViewModelsResolved()
Every binding is resolved and pointed at its source.
OnContentPushed()
Every bound widget is filled and every readout bound.
OnBarsBuilt()
The tab bar and bottom bar are built. Bind extra buttons here.
OnRecordChosen(BindingId, RecordId), OnItemChosen(BindingId, ItemId), OnRailOptionChosen(BindingId, OptionId)
A row, an item or a filter chip was clicked.
InterceptBack()
Runs before Back closes the screen. Return true when you handled it.

What you see

Open your screen from the raid HUD and it appears on the Game Menu layer over the HUD, with the tracked task's title and description. With no task tracked it shows your empty state instead. Escape or the back button closes it, and the layer below takes input back.
