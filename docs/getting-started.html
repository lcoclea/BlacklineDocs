Getting started

This page takes you from a fresh install to a working hub screen, then to your first piece of content. Everything here is done in the editor and in Blueprint. You do not need C++.

Requirements#

  • Unreal Engine 5.8. The plugin builds for Windows and Linux.
  • A Blueprint or C++ project. Blackline works in both.
  • Three engine plugins, which Blackline enables for you: CommonUI, ModelViewViewModel and EnhancedInput.

Blackline needs no other plugin from its author. Its player subsystems are not created on a dedicated server.

Install and enable#

  1. Install from Fab Add Blackline to your library on Fab, then install it to your 5.8 engine from the Epic Games Launcher.
  2. Enable it Open your project, go to Edit > Plugins, find Blackline in the UI category and tick it. The editor enables CommonUI, ModelViewViewModel and EnhancedInput with it. Restart when asked.
  3. Use the CommonUI viewport In Project Settings > Engine > General Settings, set Game Viewport Client Class to CommonGameViewportClient. CommonUI routes its input through that class, and the demo project is set up the same way.

The plugin's content mounts under /NVSBlackline/. The screens are Widget Blueprints in /NVSBlackline/Screens/, such as W_MainMenu and W_StashScreen.

Show the hub#

One Blueprint node puts a screen on the viewport. It builds the layer stack for the player the first time it runs, so there is nothing to set up first.

  1. Open your player controller Blueprint Any Blueprint that knows the player controller works, such as your HUD or game mode.
  2. Add Show Screen By Tag on Begin Play Drag from Event BeginPlay and add Show Screen By Tag from NVS View Screen Library. Plug Self into Player and pick NVS.View.Screen.MainMenu as the Screen Tag.
  3. Press Play The hub opens over your level.

Each screen class names the layer it belongs on, so the node never asks for one. The screen registry DA_BlacklineScreenRegistry maps every NVS.View.Screen.* tag to the Widget Blueprint that opens for it.

A few more nodes on NVS View Screen Library cover most of what a game does with screens:

Show Screen(Player, Screen)
Opens a screen by its class instead of its tag.
Close Screen By Tag(Player, ScreenTag) and Close Top Screen(Player)
Closes one screen, or the topmost one as Escape does.
Is Screen Open(Player, ScreenTag)
True while that screen is showing.
Open Loot Screen(Player, LootOwner)
Opens the raid inventory with a crate's or a body's items beside the player's.
Refresh Source(Player, Source)
Redraws every open screen that reads a source, after its values change.
If you prefer C++, the same functions are static members of UNVSViewScreenLibrary in the NVSViewWidgets module, such as UNVSViewScreenLibrary::ShowScreenByTag(PlayerController, ScreenTag). Add "NVSView" and "NVSViewWidgets" to your Build.cs to call them.

What you see#

The hub opens on the Menu layer, so the cursor is free and gameplay input stops. Press Escape and it closes, because Escape removes the topmost screen.

Your project has no content yet, so screens that list content tell you so. Open the traders from the hub and you see an empty state card titled No traders yet. Under it, outside a Shipping build, a line in the accent colour names what to create, here Trader Definition data assets. See Empty states for the full list.

When the last screen closes, the plugin does not restore game input for you. Keep a HUD screen such as W_RaidHUD on the Game layer, or set your own input mode when you close the last menu.

Add your first data asset#

Content in Blackline is data. Each item, trader, task, station or raid map is its own data asset, and the plugin finds them by itself. Here is a trader.

  1. Create the asset In the Content Browser, right-click and choose Miscellaneous > Data Asset. Pick Trader Definition and name it, for example PDA_Quartermaster.
  2. Fill it in Open it and set Display Name, Trade and Blurb. To give the trader a shelf, add rows to Shelf, each naming an Item Definition and its stock.
  3. Press Play and open the traders The empty state is gone and your trader has a card. There is nothing to register and no list to edit.

Every field has a tooltip. The other kinds of data asset are listed on Architecture, and each has its own guide, starting with Items.

The demo project#

The quickest way to see what a finished setup looks like is the free Blackline Demo. It is a small playable raid loop built only from Blueprints and data assets, so you can open any part of it and copy it into your game.

  • BlacklineDemo-Win64.zip is a playable Windows build. Unzip it and run BlacklineDemo.exe.
  • BlacklineDemo-Linux.zip is a playable Linux build. Unzip it and run BlacklineDemo.sh.
  • BlacklineDemo-Project.zip is the project itself.
  1. Install Blackline The project lists the plugin, so install it into your 5.8 engine first.
  2. Add the FPS Weapon Bundle The demo's guns use the free FPS Weapon Bundle from Fab. It is not in the zip, because its licence does not allow passing it on. Add it to the project from Fab so it lands at /Game/FPS_Weapon_Bundle.
  3. Open and play Open BlacklineDemo.uproject. It opens on /Game/Maps/L_BlacklineDemo. Press Play and the hub opens.

The demo also carries the example characters, outfits and hair (CC0 packs by Quaternius) as Wardrobe Piece Definitions. They are not part of the plugin. Without wardrobe pieces of your own, the character screens draw a mannequin of basic shapes.
