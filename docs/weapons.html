Weapons

A weapon in Blackline is an Item Definition whose type is Weapon. This guide makes a carbine, its magazine and a scope from the free FPS Weapon Bundle on Fab, fits the parts by dragging, and shows the result on the raid HUD and in the player's hands. You need no C++ for any of it.

Make the gun#

Add the FPS Weapon Bundle from Fab to your project. Its meshes land under /Game/FPS_Weapon_Bundle/Weapons/Meshes/. Any static mesh of your own works the same way.

  1. Create the asset In the Content Browser, right-click and pick Miscellaneous > Data Asset, then Item Definition. The demo names its carbine PDA_AR4.
  2. Fill the item fields Set Display Name, Description, Footprint (4 by 1 for a rifle), Value, Weight and Tags. A tag such as Item.Weapon.Rifle puts it under your Weapons category.
  3. Pick the type Set Type to Weapon. The weapon's own fields appear under it.
  4. Give it a look Under Look, set Static Mesh to SM_AR4. Tiles, the paper doll and the inspect window now render that mesh. To use a flat picture instead, set Icon.

The Weapon type has these fields:

Equip Slot
Where it is carried: NVS.View.Slot.Primary, Secondary, Sidearm or Melee. This is what puts Equip in the item menu. The editor reports an error when it is empty.
Calibre
A tag of your own, shown on the inspect sheet as the calibre.
Fire Modes
Picked from a list: Semi, Burst, Auto, Bolt and Pump. The first is the one the gun starts in. The inspect sheet lists them all and the raid HUD shows the first, as SEMI or AUTO.
Attachment Slots
The places a part can go. Each slot has a Slot tag that must be unique on the gun, a Label such as MAG, an Accepts list of part kinds, and a Socket and Offset that say where a fitted part sits on the mesh.

The demo's AR-4 has two slots. The optic rail accepts Attachment.Optic. The magazine well accepts Attachment.Magazine.AR4, so only the AR-4's own magazine fits it.

The bundle's meshes carry no sockets, so the demo places each slot with Offset alone. Moving those points until a part lines up is covered in Placing weapon parts.

Make the parts#

Parts are Item Definitions too. Two types can be fitted to a gun.

Attachment
One field, Kind, such as Attachment.Optic. A slot takes the part when its Accepts list matches the kind. An attachment with no kind fits nothing, and the editor says so.
Ammo
Calibre, Kind and Capacity. A magazine sets Kind to the slot kind it loads into and Capacity to its rounds. Loose rounds leave both empty.

Add the Stackable trait to a magazine if you want several in one cell. The demo stacks them three high.

Fit a magazine or a scope#

The player fits a part by dragging it onto any of these:

  • The gun's tile in a grid.
  • The worn gun on the paper doll.
  • A slot in the gun's inspect window.

The part goes into a slot that accepts its kind and is still empty. Dragging one magazine off a stack fits one and leaves the rest where they were. Dragging the part out again takes it off.

In Blueprint, the Inventory component's Attach Item does the same. It takes the part's instance, the gun's instance and the slot tag, and returns false when the slot does not take that kind or is already full.

A kit can start with parts already fitted. In a Loadout Definition or in the component's Starting Items, set Fitted To Slot on the magazine to the slot the gun is worn in. The demo's starter kit fits an AR-4 magazine to the gun worn in NVS.View.Slot.Primary, so the player starts with a loaded carbine.

Fitted parts show on the gun#

Once a part is fitted, the gun's picture shows it everywhere the gun is drawn: its tile, the doll, the inspect window, the character figure and the gun in the player's hands. Each part sits at its slot's Socket and Offset. Icons are cached by everything in the look, so fitting a scope renders a fresh icon by itself.

How the gun hangs on the character's body while worn comes from Worn On and Worn Offset on its type. That, and lining up each slot, is the subject of Placing weapon parts.

The raid HUD weapon readout#

The raid HUD (W_RaidHUD) shows the gun in hand from its Weapon binding. The built-in source is UNVSViewHeldWeapon. With an Inventory component on the player's pawn it reads the gun worn in its Held Slot and shows:

  • The gun's name.
  • Its first fire mode, such as SEMI.
  • The fitted magazine's capacity as rounds, such as 30/30.
  • How many more magazines of the same item the player carries, such as ×6 MAG. Magazines in the stash do not count.

Held Slot defaults to NVS.View.Slot.Primary. With nothing worn there the readout shows Unarmed Text, which defaults to Unarmed.

Blackline does not count shots. The readout always shows the fitted magazine full. To show live ammunition, give the HUD your own source as described below.

Show live ammunition#

  1. Make a component Create a Blueprint Actor Component, for example on your player controller, and add the interface NVS View Record Source.
  2. Answer Describe Record Fill the record: Headline for the gun's name, Status Text for the fire mode, Secondary Value for rounds left, Secondary Suffix for the capacity such as /30, and Primary Value for spare magazines such as ×2 MAG. Return true.
  3. Stand in for the built-in source On Begin Play, call Set Screen Source with Replaces set to NVS View Held Weapon and Source set to self.
  4. Redraw after a change After a shot, a reload or a fire mode switch, call Refresh Source with the player controller and self.

The demo's BPC_Vitals and BPC_RaidClock are built the same way for the vitals and the clock. See Health and vitals.

The gun in the player's hands#

Show Held Item on NVS View Look Library puts an item and everything fitted to it on a Static Mesh component in your world:

// NVSViewLookLibrary.h
static TArray<UStaticMeshComponent*> ShowHeldItem(const UObject* WorldContext, UStaticMeshComponent* Base, UObject* Holder, FName InstanceId);

The demo character does it in Blueprint:

  1. Add a mesh Add a Static Mesh component under the camera, called HeldWeapon in the demo, with collision off.
  2. Listen for changes Bind the Inventory component's On Inventory Changed to an event.
  3. Find the gun In that event, call Get Equipped on the inventory with NVS.View.Slot.Primary.
  4. Show it When something is worn, call Show Held Item with HeldWeapon as Base, the inventory as Holder and the entry's Instance Id. When nothing is worn, call it with Instance Id left as None, which empties the mesh.

Calling it again replaces what it added, so fitting or removing a scope updates the gun in hand on the next change. It uses the look's Static Mesh. Positioning the gun in view is covered in Placing weapon parts.

Optional looks for items that are not definitions#

Everything above reads the look from the Item Definition. If your game shows items that have no definition, such as ids from your own inventory system, the renderer asks the look source instead. That is an object implementing INVSViewLookSource:

// Interfaces/NVSViewLookSource.h
UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "NVS|View|Look")
NVSVIEW_API bool DescribeItemLook(FName ItemId, FNVSViewLook& OutLook);

The built-in look source is UNVSViewCharacterLooks, which also dresses the character figures. To use your own, create a Screen Source Definition with Replaces set to NVS View Character Looks and Class set to your class. The renderer reads it when the game instance starts, so begin a new Play session after changing it. A C++ subclass of UNVSViewCharacterLooks that overrides DescribeItemLook_Implementation and calls Super for ids it does not know keeps the figures working.

Result#

Open the stash in the demo, drag an AR-4 magazine onto the carbine and double-click the gun. The inspect window shows the magazine in the MAG slot and the rendered gun with it in place. Deploy, and the raid HUD reads AR-4 carbine with 30/30, while the gun in your hands carries the same magazine.
