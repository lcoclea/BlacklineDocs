Most problems with Blackline leave a line in the Output Log. Start there, find the symptom below, and apply the fix.

Read the log first

The plugin logs on two categories. LogNVSView covers layers, screens, sources and settings. LogNVSViewRender covers icons and the character preview. Warnings show at the default verbosity. To see routine messages too, type these in the console and filter the Output Log on NVSView:

A screen shows its empty state

A card such as No traders yet over a screen means the screen found nothing to show. That is what a project with no content looks like, and nothing is broken. Outside Shipping builds, the accent-coloured line under the title names what to create.

If you have added the assets and the card still shows:

  • Check the asset is really of that class. Open it and look at the class name at the top of the Details panel.
  • Check the asset's list is not empty. A Station Definition with no recipes still leaves the workbench empty.
  • For the stash, check the Inventory component is on the pawn the player controls, and that the screen's Shows Player Inventory is still ticked.
  • If you edited a screen's Empty When Bindings, look for ... decides its empty state by the binding '...', which it does not hold, so it never shows one. The id must match a binding in the same screen's View Model Bindings.

To change the words or turn an empty state off, see Set or change an empty state.

Guns have no model in the demo project

The demo's guns, magazines, scope and grenade use models from the free FPS Weapon Bundle on Fab. The project zip leaves it out, because its licence does not allow passing it on. Without it, those items have no rendered picture and the first-person gun is missing.

  1. Get the bundle Add the FPS Weapon Bundle to your Fab library.
  2. Add it to the demo project Add it from Fab into BlacklineDemo so it lands at /Game/FPS_Weapon_Bundle. The item definitions look for it at exactly that path.
  3. Restart the editor Then press Play and open the stash.

Until then, LogNVSViewRender warns Look asset ... did not load; it is left out. once for each missing mesh. The playable Windows build already has the bundle cooked in.

Text is in the engine's default font, or the theme looks wrong

Every component takes its colours, sizes and font from a style asset. When a component's own Style is unset, it uses StyleAsset on the View Setup Definition in force. If that does not load, components fall back to built-in colours with no font, so text draws in Slate's default font, and LogNVSView warns No style asset loaded from '...'.

  1. Find the setup in force A View Setup Definition in your project wins over the plugin's DA_BlacklineSetup. If you made one, check its StyleAsset names an asset that exists. The default is /NVSBlackline/DA_BlacklineStyle.
  2. Check the font Open the style asset and check its font is set. The shipped one uses /NVSBlackline/Fonts/F_JetBrainsMono.
  3. Check overrides A Style set on a screen or component wins over the setup. Clear it to use the setup's.

The character is a mannequin of basic shapes, or empty

A figure made of cylinders and a sphere

Your project has no Wardrobe Piece Definitions with a body piece, so the figure falls back to a mannequin of basic shapes. The example characters are not part of the plugin. They ship with the Blackline Demo project.

  • Create Wardrobe Piece Definitions for your own character, including a body piece. See Character looks.
  • Or copy the demo's Wardrobe and Examples folders into your project, keeping their paths.

Nothing at all

  • A mesh or material in the look did not load. LogNVSViewRender warns Look asset ... did not load; it is left out.
  • The preview is drawn by the icon renderer, which is not created on a dedicated server.

See Rendering.

A panel stays blank after you set your own source

...'s binding '...' names a ... its ... does not take: it will show nothing.Your source does not implement the interface that binding reads. In a Blueprint, add the interface under Class Settings > Implemented Interfaces. See Interfaces.

If nothing is logged and the values are stale, your source changed after the screen last read it. Call Refresh Source with your source whenever its values change, as the demo's BPC_Vitals does.

Input stays in menu mode after the last screen closes

Each layer has its own input config, and the highest occupied layer that decides input wins. When every layer is empty, the plugin changes nothing, so restoring game input is up to your game.

  • The simplest fix is to keep a HUD screen such as W_RaidHUD open on the Game layer. Its layer puts the game back in control when a menu above it closes.
  • Or, in Blueprint, call Set Input Mode Game Only and hide the cursor after you close the last menu with Close Screen By Tag or Close Top Screen.

In C++, UNVSViewLayerSubsystem::OnLayerActivationChanged() fires with an empty tag when no layer decides input any more.

Escape closes the wrong thing, or nothing

  • Escape, and the other keys in BackKeys on the Engine Settings Setup Definition, close the active screen of the topmost layer that shows one.
  • Screens with Ignores Back are passed over. The raid HUD and the notifications have it set, so Escape goes to the screen below them.
  • A screen can handle Back itself first. Screens clear a selected tile on the first press, and the settings screen reverts a pending display change while its keep prompt is up.
  • While a settings dropdown is open or a key-bind row is listening, the back keys go to that widget.
  • The raid inventory also closes on the keys in its Close Keys, so the key that opens it closes it too.

The raid loop does not go where you expect

  • The raid map's level does not open. The plugin never loads levels. The deploy queue pushes the raid HUD and calls Begin Raid, and your game opens the level of the chosen map. Get Selected Raid Map and Get Raid Map Definition give you its Level.
  • Interacting with a crate shows nothing to loot. The actor passed to Open Loot Screen needs an Inventory component. With no owner, the screen shows the player's gear alone.
  • The debrief is empty. Call End Raid on the raid session before the debrief opens.
  • Everything was lost on death. Missing in action forfeits everything carried except what the Inventory component's Kept On Death slots hold. Add the secure case slot there.

A notification never goes away

A payload with a Duration of zero or less stays until it is dismissed. Call Dismiss on the notification subsystem with its tag, or Dismiss All. Give every other payload a positive duration. The default is 4 seconds. See Notifications.

The hideout does not do what you expect

  • The upgrade button says Load the parts. The next level lists items in its Parts, and not all of them are loaded yet. Drag each item from the stash onto its slot under the level. The count on the button, such as 1 / 2, says how many are in. If the stash does not hold enough, buy or find the rest. Leave Parts empty on a level that should cost only cash.
  • The upgrade button says Not enough cash. Every part is loaded but the session wallet is short of the level's Cost. Sell something or hand in a task, then come back. The loaded parts stay loaded.
  • Crafts stopped and the bench says NO POWER. The generator is out of fuel. Open the generator and press Add fuel, or drag a fuel can from the stash onto an empty slot of the tank. Paused crafts carry on from where they stopped. To run a hideout without fuel at all, set the generator's Hours Per Can to 0.
  • Add fuel reads No fuel in the stash. The stash holds none of the generator's Fuel Item. Check that Fuel Item names the same Item Definition the player picks up or buys.
  • Add fuel reads Every slot is full. Every slot holds some fuel. A part can counts as full and cannot be topped up, so wait for it to burn out, or upgrade the generator for more Fuel Slots.
  • Fuel never goes down. Fuel burns only while a craft is running. If it still stays put during a craft, the generator's Hours Per Can is 0, which never burns.
  • A new player's tank is empty. The generator's Starting Fuel list is empty. Add one entry per slot, such as 1 for a full can.
  • Worn trousers and the wardrobe's trousers both show on the figure. Worn clothing is drawn on top of the wardrobe and does not hide it. Dress the wardrobe to match, for example with a starting outfit that has no trousers, or a piece in that slot that sits under the worn item. See Character looks.

Things that are not bugs

  • A bench refuses to start a craft right after an upgrade. It is down for its level's Downtime. The bench screen shows when it is back.
  • A second player sees nothing of the first player's inventory. The Inventory component does not replicate. Blackline is single player as shipped.
  • Only the character screen's figure moves. Every other preview is still on purpose, and none zooms or swoops.
