Source interfaces

This is the full list behind Connecting your game: the nine interfaces the screens read, the order a screen picks its source in, and every field of the structs they return. Read the guide first. You only need this page for a value the guide does not cover, or to write a source in C++.

How a screen gets its data#

A screen never reads your game's types. Each of its bindings asks a source for plain structs, such as a list of meters or a container's items, and a viewmodel publishes them to the widgets. Every binding names a built-in source class, such as UNVSViewVitals for the raid HUD's vitals, and your object stands in for that class.

Which source a binding uses#

A screen binding resolves its source in this order. The first one found wins:

  1. An object passed to SetBindingSource on that open screen.
  2. The binding's SourceObject, set on a screen's class defaults.
  3. An object registered with Set Screen Source for the binding's built-in class.
  4. A Screen Source Definition that replaces the binding's built-in class.
  5. A new instance of the binding's built-in SourceClass.

SetBindingSource is Blueprint callable on any screen. Use it to point one binding of one open screen at a live object. SetInventoryOwner does the same for every container binding at once.

The nine interfaces#

All nine live in the NVSView module under Public/Interfaces. Each is Blueprintable and every function is a BlueprintNativeEvent, so a Blueprint can implement it from Class Settings. The default implementation returns nothing, and a binding whose source returns nothing shows nothing.

The context id#

Every function takes an FGuid, named SetId, ContainerId, RecordId and so on. It tells a source that serves several sets which one is wanted. A source that serves one set, like BPC_Vitals, ignores it.

  • For a binding as a screen opens, the id is made from the binding id with FGuid::NewDeterministicGuid, so Stash always gives the same id.
  • When a screen asks about one record, such as the trader the player picked, the id is made from that record's id. UNVSViewDefinitionLibrary::ContextFor(FName RecordId) returns the same value in C++.

When a screen reads again#

A screen reads every binding when it opens, again straight after it raises a request, and whenever Refresh Source names its source. RefreshViewModels() on a screen re-reads all of its bindings and is Blueprint callable. The market screen also asks its market source once a second.

INVSViewContainerSource#

A grid container's description and its items. Each open container gets its own viewmodel, told apart by the context.

bool DescribeContainer(const FGuid& ContainerId, FNVSViewContainerDescription& OutDescription)
Fill the container's label, name and size. Return false for an unknown container and leave OutDescription untouched.
void GetContainerItems(const FGuid& ContainerId, TArray<FNVSViewContainerItem>& OutItems)
Fill the items. Reset OutItems first so an unknown container reads as empty.
FNVSViewContainerDescriptionMeaning
FText Label, FText ContainerName, FText NoteTextThe container's kind (such as BACKPACK), its name and a note line.
FIntPoint GridSizeSize in cells.
bool bSearchedFalse veils the contents until the player searches. Defaults to true.
bool bOnBodyThe container is on a body, which shortens the search.
bool bLockedLocked shut, like a secure case on a body. Contents are hidden and nothing goes in or out.
FGameplayTag PlaceWhere its items sit, under NVS.View.Place, which decides their menu rows. Empty counts as the stash.
FGameplayTagQuery Accepts, FText RefusalTextWhich items it takes, and what the player is told when it refuses one. Empty takes anything.
FNVSViewContainerItemMeaning
FName ItemIdYour handle for the item. Requests name it.
FIntPoint TopLeft, FIntPoint FootprintTop-left cell, and size in cells with rotation already applied.
FText DisplayName, FText TagText, FText SecondaryValueThe name, the short tag and the figure under the name. Empty fields are not drawn.
ENVSViewColorRole TintRoleThe tile's tint.
bool bQuestLit, bool bUnaffordableAn item an active task wants, and one the player cannot afford.
FGameplayTagContainer ItemTagsThe item's own tags, which categories, slots and containers match against.
FGameplayTag FitsSlot, FGameplayTag BlocksSlotThe doll slot it is worn in, and the slot it rules out while worn. Both under NVS.View.Slot.
TSoftObjectPtr<UTexture> RenderArtA picture for the inspect window.
bool bUsableOffers a Use row. Your game applies the effect.
FName InsideIdThe container this item opens, such as a pack. None when it opens nothing.
FGameplayTag AttachKindThe attachment kind it is, such as Attachment.Optic. Empty for an item that is not an attachment.
int64 Price, int32 CountWhat one costs or fetches in whole currency units, and how many are stacked here.

Most games use the plugin's Inventory component, which needs neither this interface nor the slot set one. Implement both only for an item system of your own, and hand the screen your object with SetBindingSource. See Containers.

INVSViewFilterSource#

The options of a filter rail, such as the stash categories. The selected option and the search text belong to the viewmodel and are never asked of the source.

bool GetFilterOptions(const FGuid& SetId, TArray<FNVSViewFilterOption>& OutOptions)
Fill the options. Return false when nothing narrows this set. Empty OutOptions either way.
FNVSViewFilterOptionMeaning
FName OptionIdThe option's id.
FText LabelThe caption, or the tooltip when an icon is drawn.
FName IconIdThe icon the rail draws. None shows the label.
int32 MatchCountHow many entries the option matches. Negative paints no count.
FGameplayTagContainer MatchTagsItems carrying any of these tags, or a tag below them, match. Empty matches everything, like an All option.

The stash's categories come from your Item Category Definitions, so most games never implement this. See Items.

INVSViewLookSource#

What items and characters look like, so the renderer can build them in its studio world.

bool DescribeItemLook(FName ItemId, FNVSViewLook& OutLook)
Describe the item a tile or slot names. Return false when the item has no look.
bool DescribeCharacterLook(const FGuid& ContextId, FNVSViewLook& OutLook)
Describe a character. ContextId is the screen's viewmodel context, so a crewmate's card asks for that crewmate.

An item id that names an Item Definition is drawn from that definition's Look without asking the source, so items authored as data need no look source at all. The built-in UNVSViewCharacterLooks dresses the figure from your Wardrobe Piece Definitions, or shows a mannequin of basic shapes without them.

The renderer makes its look source once, when the game instance starts, from the UNVSViewCharacterLooks slot. Replace it with a Screen Source Definition whose Replaces is NVSViewCharacterLooks. From C++ you can also swap it at run time with UNVSViewIconRenderer::Get(WorldContext)->SetLookSource(Source).

Live figures rebuild after a wardrobe or equipment request only when the look source derives from UNVSViewDataAsset and its ApplyRequest returns true. Derive your look source from UNVSViewCharacterLooks or UNVSViewDataAsset if you use the character screen. In C++, UNVSViewIconRenderer::RefreshFigures() rebuilds every live figure after a change made outside a request.

See Rendering and Character looks for what a look holds.

INVSViewMapMarkerSource#

The markers on a map plate. The details behind a selected marker come from a record source, asked under that marker's context.

bool GetMapMarkers(const FGuid& PlateId, TArray<FNVSViewMapMarker>& OutMarkers)
Fill the markers. Return false when nothing is marked. Empty OutMarkers either way.
FNVSViewMapMarkerMeaning
FName MarkerIdThe marker's id.
FVector2D PositionPosition as a 0 to 1 fraction of the plate on each axis, so it holds at any plate size. Not clamped.
FText Label, FText StatusTextThe marker's name and an optional status line.
ENVSViewColorRole TintRoleThe marker's colour.
bool bSelectableWhether a click selects it. Informational markers such as exits leave it false.

The location screen places one point per Raid Map Definition, so a game with raid maps authored as data does not need this.

INVSViewMarketSource#

Everything the market screen shows, in one struct. The screen asks once a second. Types are in Market/NVSViewMarketTypes.h.

bool DescribeMarket(const FGuid& ContextId, FNVSViewMarket& OutMarket)
Fill the market. A false return empties the screen.
FNVSViewMarketMeaning
TArray<FNVSViewListing> ListingsListings on the board. Each listing's state is Open, Leading, Outbid, Ended or Won.
TArray<FNVSViewOwnListing> MyListingsThe player's listings, each Live, Sold or Expired.
TArray<FNVSViewMarketType> CatalogueEvery item type the market knows.
FNVSViewMarketWallet WalletCash, escrow, money to collect, listing slots and the fee rates.

The built-in UNVSViewMarketBoard runs a market offline on a clock and answers every market request itself. A networked market replaces it. See Market and trading.

INVSViewMeterSource#

Measured figures for a set, such as vitals, a raid clock or a cash balance. This is the interface the demo's two Blueprint components implement.

bool GetMeters(const FGuid& SetId, TArray<FNVSViewMeter>& OutMeters)
Fill the meters. Return false when nothing is measured. Empty OutMeters either way.
FNVSViewMeterMeaning
FName MeterIdThe id screens look the meter up by. See the names the screens look for.
FText LabelThe caption, such as CARRY.
FText ValueTextThe figure as your game formats it.
double Value, double MaxValueDrive the fill and the colour band. A MaxValue of zero is open ended and draws no bar.
double WarnFraction, double CriticalFractionWhere the band turns to warning and critical. Defaults 0.8333 and 1.0.
bool bLowIsAdverseWarn below the fractions instead of above, as health does.
ENVSViewColorRole NominalRoleThe colour below the warning band. Default Success.

A meter source in C++#

The same component as the guide's Blueprint, written in C++.

// MyVitalsComponent.h
#pragma once

#include "Components/ActorComponent.h"
#include "Interfaces/NVSViewMeterSource.h"

#include "MyVitalsComponent.generated.h"

UCLASS(meta = (BlueprintSpawnableComponent))
class UMyVitalsComponent : public UActorComponent, public INVSViewMeterSource
{
	GENERATED_BODY()

public:
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Vitals")
	float Health = 100.0f;

	virtual void BeginPlay() override;
	virtual bool GetMeters_Implementation(const FGuid& SetId, TArray<FNVSViewMeter>& OutMeters) override;

	/** Call when Health changes so open screens redraw. */
	void Redraw();
};

// MyVitalsComponent.cpp
#include "MyVitalsComponent.h"

#include "Definitions/NVSViewDefinitionLibrary.h"
#include "NVSViewScreenLibrary.h"
#include "Sources/NVSViewMeterLists.h"

void UMyVitalsComponent::BeginPlay()
{
	Super::BeginPlay();
	UNVSViewDefinitionLibrary::SetScreenSource(UNVSViewVitals::StaticClass(), this);
}

bool UMyVitalsComponent::GetMeters_Implementation(const FGuid& SetId, TArray<FNVSViewMeter>& OutMeters)
{
	OutMeters.Reset();
	FNVSViewMeter& Hp = OutMeters.AddDefaulted_GetRef();
	Hp.MeterId = TEXT("Vitals.Health");
	Hp.Label = INVTEXT("HP");
	Hp.ValueText = FText::AsNumber(FMath::RoundToInt(Health));
	Hp.Value = Health;
	Hp.MaxValue = 100.0;
	Hp.bLowIsAdverse = true;
	Hp.WarnFraction = 0.5;
	Hp.CriticalFraction = 0.25;
	return true;
}

void UMyVitalsComponent::Redraw()
{
	UNVSViewScreenLibrary::RefreshSource(GetWorld()->GetFirstPlayerController(), this);
}

Add NVSView and NVSViewWidgets to your module's dependencies.

INVSViewRecordSource#

Named records and record lists. Most screens are built from it, from trader cards to task steps.

bool DescribeRecord(const FGuid& RecordId, FNVSViewRecord& OutRecord)
Fill one record, for a detail pane. Return false for an unknown record and leave OutRecord untouched.
void GetRecords(const FGuid& SetId, TArray<FNVSViewRecord>& OutRecords)
Fill a list. Reset OutRecords first so an unknown set reads as empty.
FNVSViewRecordMeaning
FName RecordIdThe record's id. Clicks, tabs and requests name it.
FText Headline, FText SubtitleThe main line and the line under it.
FText StatusText, ENVSViewColorRole StatusRoleA short status, such as IN USE, and its colour.
FText PrimaryValue, FText SecondaryValue, FText SecondarySuffixTwo figures, and smaller text after the second, such as the "/30" in "24/30".
FText BodyLonger text shown in a detail pane.
ENVSViewColorRole AccentRole, FName IconIdThe row's accent, and an icon looked up in the screen's art table.
FGameplayTag StateThe record's state under NVS.View.State, such as NVS.View.State.Ready. Screens make decisions from this, while StatusText is only the label they show.
FGameplayTagContainer TagsWhat the record is about, such as the item a part slot wants.
float FractionA 0 to 1 figure drawn as a bar, such as standing. Below 0 draws none.
double Number, int32 Count, int32 OfFigures a screen computes with, such as a price, a stock count, or a tally out of Of.
FText DurationHow long it takes, such as a recipe's craft time.

Empty fields are not drawn. In Blueprint, implement Get Records by building an array of NVS View Record structs. A source that only fills a list can leave Describe Record returning false.

INVSViewSettingValueSource#

Reads and writes setting values. The settings registry describes each row, and your game keeps the values wherever it already stores them. This is the one interface that writes.

bool GetSettingValue(FName SettingId, FNVSViewSettingValue& OutValue)
Fill the value. Return false for an unknown setting and leave OutValue untouched.
bool SetSettingValue(FName SettingId, const FNVSViewSettingValue& Value)
Store the value. Return false to reject the write, and the row shows the value you kept.

FNVSViewSettingValue holds a Kind (Bool, Enum, Slider or Keybind) and one field for each: bBoolValue, OptionIndex and Number. Key bindings have no field, because Enhanced Input already stores them. The shipped settings screen uses UNVSViewEngineSettingsSource, which applies each row to the engine. See Settings.

INVSViewSlotSetSource#

A set of equipment slots, such as what the player wears, a saved loadout or a looted body.

bool DescribeSlotSet(const FGuid& SetId, FNVSViewSlotSetDescription& OutDescription)
Fill the panel's Label, Title and NoteText. Return false for an unknown set and leave OutDescription untouched.
void GetSlots(const FGuid& SetId, TArray<FNVSViewSlotEntry>& OutSlots)
Fill every slot, empty ones included, since the panel draws every slot. Reset OutSlots first.
FNVSViewSlotEntryMeaning
FName SlotId, FText LabelThe slot's id and its own name, such as HEAD.
FText ItemName, FName ItemId, float WeightKgThe worn item's name, id and weight. Ignored while empty.
bool bFilled, bool bStrippedWhether something is worn, and whether the slot is unavailable.
bool bFixedThe worn item cannot be taken, like trousers on a body. It shows faded and cannot be dragged.
FGameplayTagQuery AcceptsExtra items the slot takes on top of items made to be worn there.
FGameplayTag BlocksSlotThe slot the worn item rules out.
ENVSViewColorRole TintRoleThe colour of a filled slot's mark.
int32 MountCount, int32 FittedCount, FName MountedOnSub-slots a slot carries and how many are filled. A sub-slot names its parent in MountedOn and gets no tile.

In C++, NVSViewDeriveMounts(TArray<FNVSViewSlotEntry>& Slots) recomputes the mount counts from the sub-slot rows. See Equipment.
