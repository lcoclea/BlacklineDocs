Connecting your game

Blackline's screens work out of the box with example values. To show your game's real values, such as the player's health or the time left in a raid, you add one small Blueprint component that hands them over. This page builds one step by step, and you will not need any C++.

The idea in one minute#

Each screen gets its values from a source. Blackline ships a source for every screen, which is why a fresh install shows example numbers or an empty state. To connect your game, you give Blackline your own source for the values you care about. Everything else keeps working as it did.

  1. The raid HUD opens and needs the player's health, food and water.
  2. Blackline checks whether your game gave it a source for those values. If it did not, it uses its own.
  3. Your Blueprint component fills in a short list, such as health 72 out of 100.
  4. When health changes, your component calls Refresh Source and every open screen updates.
Most of your content never needs this. Items, traders, tasks, stations and raid maps are data assets the screens find by themselves. A source is only for values your game changes while it runs.

Look at the demo's example first#

The Blackline Demo project has two working components you can open and copy. Both are in /Game/Demo/Sources.

  • BPC_Vitals hands over health, food, water and carried weight.
  • BPC_RaidClock hands over the time left in the raid and on the exit.

Open BPC_Vitals next to this page. Each step below matches something you can see in it.

Build your own vitals component#

  1. Create a Blueprint component In the Content Browser, right-click and pick Blueprint Class, then Actor Component. Add it to your player controller, so it lives as long as the player does.
  2. Add the interface Open Class Settings. Under Implemented Interfaces, add NVS View Meter Source. A meter is one value with a maximum, like health out of 100.
  3. Fill in your values In the My Blueprint panel, under Interfaces, open Get Meters. Add one Make NVS View Meter node per value. Set its Meter Id from the table below, its Value and Max Value from your game, and its Value Text to the text the player should read. Put the nodes into a Make Array, connect it to Out Meters and return true.
  4. Tell Blackline to use it On Begin Play, call Set Screen Source. Set Replaces to NVSViewVitals, which is Blackline's own vitals source, and connect Self to Source.
  5. Update the screens Whenever a value changes, call Refresh Source with your player controller and Self. A looping timer is fine too. BPC_Vitals refreshes four times a second.

For health, food and water, tick Low Is Adverse so the bar warns as it runs low. The demo warns at half and turns red at a quarter, with a Warn Fraction of 0.5 and a Critical Fraction of 0.25.

The names the screens look for#

A screen finds each value by its Meter Id. Use these names, and set Replaces to the source in the first column:

ReplacesMeter idsShown on
NVSViewVitalsVitals.Health, Vitals.Wind, Vitals.Food, Vitals.Water, Vitals.CarryRaid HUD, hub, stash, raid inventory, loadouts
NVSViewRaidClockRaid.Clock, Raid.ExfilRaid HUD
NVSViewWalletWallet.OnHand, Wallet.StashValueStash, trade, market

The screens show Value Text exactly as you write it, so format it the way you want the player to read it. BPC_Vitals writes carried weight as 21.2 / 36.0 KG. A Max Value of zero means the value has no limit, like cash, and no bar is drawn.

Things to know#

  • Call Set Screen Source before the first screen opens. A component on the player controller begins play before the controller does, which is early enough.
  • One component feeds every screen that shows the same values. The raid HUD, the hub and the stash all show your health once it is connected.
  • To go back to Blackline's own values, call Set Screen Source again with nothing connected to Source.

Values that do not change while the game runs#

For data that is the same every time, such as the player's starting injuries, you can skip the Blueprint graph and use a Screen Source Definition asset instead. Right-click in the Content Browser, pick Miscellaneous > Data Asset, then Screen Source Definition, and fill it in:

Replaces
Which of Blackline's sources this stands in for, such as NVSViewBodyZones for the health screen.
Asset
A data asset of that same kind with your rows filled in.
Class
Or a Blueprint class that answers instead. Used only when Asset is empty.
Sort Order
When two definitions replace the same source, the lowest number wins.

The demo's PDA_PlayerBodySource in /Game/Demo/Sources works this way. It points at DA_PlayerBody, which lists the player's fifteen body zones with their hit points and injuries, and the health screen shows them with no graph at all.

If your game also connects a live source for the same values with Set Screen Source, the live one wins.

What else you can replace#

These are the sources games most often swap for live values. Each one is replaced the same way as vitals.

ReplacesBlueprint interfaceWhat it shows
NVSViewVitalsNVS View Meter SourceHealth, wind, food, water and carried weight.
NVSViewRaidClockNVS View Meter SourceTime left in the raid and on the exit.
NVSViewWalletNVS View Meter SourceCash on hand and stash value. It already follows the session's cash.
NVSViewCompassMarksNVS View Record SourceThe marks on the HUD compass.
NVSViewCrewVitalsNVS View Record SourceYour crewmates' rows on the HUD.
NVSViewParty, NVSViewPartyChatNVS View Record SourceThe lobby's crew and chat.
NVSViewMarketBoardNVS View Market SourceThe player market. Blackline's own board runs offline.

The stash, the raid inventory and the paper doll need no source of yours. Add the Inventory component to the player's pawn and they follow it on their own. See Containers.

Every interface, every field and a C++ version of the vitals component are on Source interfaces.

What you see#

Play and deploy into a raid. The raid HUD shows your health, food and water, and they move as your game changes them. In the demo they run down during the raid, and the carried weight follows what you pick up.
