FAQ

Short answers to the questions people ask about Blackline, taken from what the plugin's code does today. Where a limit exists, the answer says so.

Before you buy#

What is in the plugin?#

The NVSBlackline plugin has five modules.

  • NVSView, runtime. The layer stack, viewmodels, interfaces and built-in sources, the data asset types, the Inventory component, the raid session, deploy queue, request and notification subsystems, the style asset and the gameplay tags.
  • NVSViewWidgets, runtime. The screens, the components and the screen library.
  • NVSViewRender, runtime. The icon renderer and the character preview.
  • NVSViewSettings, runtime. Engine-backed settings, saved settings, key rebinding and the field of view modifier.
  • NVSViewEditor, editor only.

Its content folder holds 27 screen and window Widget Blueprints, 48 component Widget Blueprints, the layer table DA_BlacklineLayout, the screen registry DA_BlacklineScreenRegistry, the theme DA_BlacklineStyle, the two setup assets, 17 context menu rows as Item Action Definitions, the JetBrains Mono font, 62 icon textures, the render materials, five character preview profiles, and the sound classes and input actions the settings screen uses. See Screens and Components.

Does a fresh install show anything?#

The screens work, but your project has no content yet. Screens that list content, such as traders, the hideout or the stash, show an empty state card instead of sample data. It tells the player there is nothing here yet and, outside Shipping builds, tells you which data assets to create. The settings screen works from the start. See Empty states.

What is the demo, and how do I get it?#

The free Blackline Demo is a small playable raid loop built on the plugin. You pick a map, deploy, loot a crate and a body, extract, then craft, trade, heal and kit up at home. It is built only from Blueprints and data assets. It comes in two downloads.

  • BlacklineDemo-Win64.zip, a playable Windows build.
  • BlacklineDemo-Project.zip, the Unreal project, with its Blueprints and data assets for you to open and copy from. It opens on /Game/Maps/L_BlacklineDemo.

The project zip does not include the free FPS Weapon Bundle from Fab, because its licence does not allow passing it on. Add it from Fab so it lands at /Game/FPS_Weapon_Bundle, or the demo's guns have no model. See Getting started.

Which engine version and plugins does it need?#

Unreal Engine 5.8. The plugin builds for Windows and Linux. Its descriptor enables three engine plugins, CommonUI, ModelViewViewModel and EnhancedInput. It needs no other marketplace plugin.

Does it work in multiplayer?#

No, it is a single player kit as shipped. The Inventory component does not replicate, and the plugin declares no replicated properties and no RPCs. Its subsystems belong to a local player (layer stack, viewmodels, requests, notifications, deploy queue, raid session, settings) or to the game instance (icon renderer), and the icon renderer is not created on a dedicated server.

A networked game can still use the screens if it does the networking itself:

  • Supply your own replicated inventory through the NVS View Item Holder interface, which the Inventory component also implements. See Interfaces.
  • Feed other screens from your replicated state with sources of your own.
  • Requests are raised on the local player only. Send the change to your server from your On Request handler, then call Refresh Source when the answer arrives.
  • The deploy queue is a local timer. It does not matchmake.

Does it support split screen?#

Each local player gets their own layer stack, viewmodels, requests and notifications, because they are local player subsystems. Call Show Screen By Tag with each player's controller and each gets their own stack.

Can I use it without C++?#

Yes. Showing screens, creating content, feeding live values and answering requests all work in Blueprint. The screen library's nodes (Show Screen By Tag, Open Loot Screen, Reveal Hud Group, Set Extract Progress, Refresh Source), the definition library's Set Screen Source and Set Selected Raid Map, the raid session's Begin Raid and End Raid, the request subsystem's On Request and Raise, and the Inventory component's functions are all Blueprint nodes. The demo's game is built from Blueprints and data assets only.

Does it support gamepads?#

Partly. Buttons are CommonUI buttons, so they take focus and follow CommonUI navigation, and the gamepad's right face button closes a screen like Escape does. Many item interactions are written for a mouse, such as dragging between grids, right-clicking for the item menu and the hover shortcut keys. Test the screens you use with a pad before you ship.

What does it cost at runtime?#

  • A screen reads its sources when it opens and when something changes. Widgets update through FieldNotify when a viewmodel field changes.
  • The icon renderer captures item icons in an isolated studio world, at most IconsPerFrame per frame (2 by default), and caches them up to IconCacheMegabytes (64 by default). See Project settings.
  • The market screen reads its source again once a second while it is open.
  • Hidden raid HUD groups are collapsed, so they cost nothing to draw.

What are the limits I should know about?#

  • Single player only, as above.
  • The raid HUD's ammo readout shows the fitted magazine's capacity. It does not count shots. See Weapons.
  • Cash, hideout progress, tasks and saved kits last for the play session. Your game saves them if they should survive a restart.
  • Blackline pays only a task's cash. Its experience, reward lines and unlocks are text for your game to act on.
  • The plugin does not load levels. Your game opens the raid map's level when the raid begins.

What licence does the bundled font have?#

JetBrains Mono, under the SIL Open Font License 1.1. The licence text ships in the plugin at Licenses/JetBrainsMono-OFL.txt, is credited in CREDITS.md, and the plugin's filter keeps both in a packaged copy.

What licence do the example characters have?#

The example characters, outfits and hair are CC0 packs by Quaternius. They ship only with the Blackline Demo project, so a game built from the plugin alone contains none of them. The demo's own Blueprints and data are yours to copy into your project.

After you buy#

How do I open a screen?#

Call Show Screen By Tag from NVS View Screen Library with the player controller and a tag such as NVS.View.Screen.StashScreen. It puts the screen on the layer its class declares and builds the layer stack first if there is none. Every screen's tag is listed on Screens.

How do I fill a screen that shows its empty state?#

Create the data assets its setup hint names, such as Trader Definitions for the traders. The plugin finds them by itself. The full list is under Empty states.

Can I edit the shipped screens?#

Yes. Make a Blueprint child of the screen's W_ asset, change it, and point the screen's row in your own screen registry at the child. Name that registry on your View Setup Definition. Everything that opens the screen now opens yours. Each screen's C++ class finds widgets by name, so keep the names it uses. When one is missing, the screen logs a warning on LogNVSView naming it.

How do I change the colours and font?#

Duplicate DA_BlacklineStyle, change its tokens and set StyleAsset on your View Setup Definition to your copy. See Theming.

Can I localise the screens?#

The screens' own words, including the empty state titles and hints, are localisable text, so they enter the localisation pipeline. The names and descriptions in your data assets are text fields too.

Something does not show. Where do I start?#

Open the Output Log, filter on LogNVSView, and see Troubleshooting.
